# Retrieval assessment

Run `python benchmark/retrieval_assessment.py` from the project root. The command copies each existing fixture to a temporary directory, builds an isolated SQLite index, performs the specified edit, rename, or removal and synchronizes again, and calls the real `broker.task_context` with a 1,200 estimated-token budget. It collapses returned source breadcrumbs to unique paths in their observed order and passes those predictions to `retrieval_eval.evaluate` at k=5. The JSON includes the labels, predictions, sync counts, forbidden paths returned, per-case metrics, and aggregate metrics. It does not modify the original fixtures, user database, or call an agent.

The eight labels in `benchmark/retrieval_cases.json` were authored by an agent for these small fixtures. They are not independently human reviewed, exhaustive, or representative of real projects. Each positive case labels one implementation file; tests and other supporting files may also be relevant, so precision is not an authoritative relevance judgment. Empty labels describe the narrowly specified fixture tasks, including the removed target; they do not establish that no related file exists. Precision@5 divides by five even when fewer than five paths are returned. Estimated tokens count the response payload, vary with temporary paths, and do not measure provider usage or savings.

On November 15, 2026, the local run returned the labelled file at rank one in all six positive cases and abstained in both negative cases. Precision@5 was 0.15, recall@5 and MRR@5 were 1.0 for positive cases, and abstention accuracy was 1.0 across eight cases. The rename and removal cases returned no forbidden old path. These results characterize this fixture run only; they do not close the human-reviewed dataset or real-task effectiveness gates in [execution plan](TOKSMART_10_OF_10_EXECUTION_PLAN.md).

## Pinned real-repository probe

Run `python benchmark/real_repo_assessment.py --repo /absolute/path/to/clean/checkout` against TokSmart commit `9cbd87034c0b496a69dfca9d01950a4547214e45`. For example, create a separate clean worktree with `git worktree add --detach /tmp/toksmart-eval 9cbd87034c0b496a69dfca9d01950a4547214e45` and pass that path. The runner verifies the commit and absence of tracked changes, indexes the checkout into a temporary database, calls the real bounded-context retrieval path with a 600 estimated-token budget, and writes per-case paths, latency, forbidden-path observations and metrics under ignored `benchmark/results/real_repo_assessment.json`. It makes no model or network calls and does not write to the source checkout.

The five [case labels](../benchmark/real_repo_cases.json) are agent-authored and include file-level rationales. They are inspectable but **not independently human reviewed or exhaustive**. On the pinned 135-file source snapshot, one local run gave recall@5 1.0 over four positive cases, precision@5 0.16, MRR@5 0.375, and abstention accuracy 1.0 after a narrow leading-verb fix. One positive query still ranked an unrelated fixture file first and returned it as a forbidden path. Precision uses the existing evaluator's five-slot denominator, even when fewer results are returned. Latency is local and machine-dependent; estimated response tokens are not provider usage. These results identify a retrieval-quality weakness and do not establish coding-task success or token savings.
