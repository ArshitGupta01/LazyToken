# Client integration evidence

This table records specific checks, not a guarantee for every release or operating system. A configuration entry and a server handshake do not prove that an assistant loads or uses the tools during ordinary work.

| Client | Evidence | Still unverified |
| --- | --- | --- |
| Codex CLI 0.169.0-alpha.11.1 on Windows | On November 15, 2026, an isolated profile generated by `setup` was read by `codex mcp get --json`; the suggested local server separately passed initialization and tool discovery. An earlier isolated run explicitly called `get_task_context`, as documented in [the pilot](BENCHMARK_PILOT.md). | Automatic tool use in typical tasks, other Codex versions, and a fresh-machine managed installation. |
| Antigravity | Setup can preview and preserve or add the documented configuration shape. The setup tests use isolated synthetic configurations. | Live client loading and tool calls, client version compatibility, and managed installation. |

To reproduce the Codex configuration check when the CLI is installed, run `python -m unittest tests.test_onboarding.SetupTests.test_codex_cli_reads_generated_registration_in_isolated_profile`. It creates a temporary project, database, and `CODEX_HOME`; it does not modify the user's client configuration. `python -m unittest tests.test_onboarding.SetupTests.test_real_local_handshake_uses_only_isolated_store` checks the server separately.

After connecting a client, restart it, inspect its tool list, and try `get_task_context` for the selected repository. The local setup connection check reports the server handshake; it cannot verify that an external client actually loaded the entry.
