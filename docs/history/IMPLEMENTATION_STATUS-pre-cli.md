# Implementation status

This document records the current implementation, not a claim that the full roadmap is complete.

- **Measurement preparation:** A draft 24-task corpus and manual-record benchmark harness exist. No real benchmark tasks have been run and no token-savings claim has been established.
- **Context broker:** Project-scoped breadcrumbs, estimated budgets, modes, conservative skip/abstain behavior, and session fingerprint deduplication are available through MCP and CLI. Default budgets remain estimates. A matching administrator-configured offline tokenizer supports strict compact JSON payload limits; provider framing is excluded and model/tokenizer equivalence is not independently verified. Bounded per-process search caching invalidates on SQLite changes. Automatic skip decisions and optimal budgets have not been evaluated.
- **Retrieval evaluation:** An offline evaluator calculates metrics from supplied labels and predictions. A validated relevance dataset, automatic comparison runs, and empirical one-hop/two-hop evaluation remain outstanding.
- **Memory:** Agents can submit proposals with task details and indexed evidence. Approval and verification are explicit; exact-name duplicate checks, freshness, and supersession are implemented. MCP and CLI review rely on trusted clients to obtain human approval; they do not independently authenticate a human. The explicit complete_task MCP/CLI checkpoint creates evidence-backed pending suggestions from caller-supplied outcomes and resolutions. Similar-summary detection and related-name conflict warnings are project-scoped heuristics. Automatic client lifecycle hooks remain pending.
- **Search:** FTS5 prefix matching is used when available and falls back to lexical ranking. Explicit source-range inspection is bounded and checks indexed scope; secret redaction is best effort.
- **Isolation:** Shared graph views now expose only global relationships. A legacy migration could previously have produced ambiguous global duplicates; the `audit_scopes` action lists possible overlaps but does not change them. Existing ambiguous data requires human review. The current default store had no overlaps when checked during this implementation.
- **Visuals:** The local dashboard has a 2D graph and an optional, locally bundled WebGL 3D explorer sharing graph data, filters, and selection. 3D depth is a visual layout aid rather than a semantic distance. The dashboard caps results at 500 nodes and 3,000 relationships and reports truncation. Broader accessibility and dense-graph performance validation remain outstanding; the graph reflects indexed assets rather than inventing project or file nodes.
- **Windows packaging:** A local PyInstaller onedir candidate and a managed PowerShell install/upgrade/rollback/uninstall helper are present. This is not a signed or published release; a clean-machine test, distribution and license review, and a complete setup wizard remain outstanding. Backup and restore create new SQLite copies and do not overwrite an existing database.
- **Remaining roadmap:** Full setup wizard and automatic task completion integration, optional semantic search, robust cross-project pattern discovery, complete user-facing analytics, release distribution, and real benchmark-backed claims remain open. See `task.md` for the full checklist.
